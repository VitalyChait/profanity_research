# MinorSafe repository audit

Reviewed commit `f8f697c` on 2026-11-20. **40 High findings, 0 Critical confirmed.** The largest risks are exposure of the Hub credential on shared hosts, contamination of held-out examples, reuse of incompatible results, and publication of measurements that the pipeline never made.

The review covered the tracked repository (148 files), following the setup, remote execution, dataset, experiment, evaluation, and publication paths. The local test suite returned **119 passed, 3 skipped** with `.venv/bin/python -m pytest -q -p no:cacheprovider`. The three skipped tests require CUDA. Validation below identifies local reproductions, evidence from existing logs, or the exact control flow that establishes a defect. GPU and remote operational findings were checked against source and configuration. This review did not run a remote benchmark or establish that credentials were acquired by another person. Third-party packages were not independently audited for vulnerabilities.

Severity reflects impact on this research repository. High means a supported workflow can expose a credential, disrupt other jobs, lose expensive results, or materially invalidate a reported study outcome. Critical would require evidence of a substantially broader compromise or loss. Each numbered finding is High.

## Remote execution and provisioning

**4. A model-load error silently enables execution of unpinned upstream code.** A `ValueError` or `KeyError` from the first classifier load causes a retry with `trust_remote_code=True` and no pinned revision. This includes ordinary configuration errors. The retry can execute model-provided Python with the benchmark account's permissions if the selected repository supplies it. Require an explicit reviewed model and immutable revision for custom code and propagate unrelated failures. [src/minorsafe/registry.py, load_encoder_classifier](src/minorsafe/registry.py)

**6. Model predownload populates a different cache from inference.** The environment sets `HF_HOME`. The downloader passes that directory directly as `snapshot_download(cache_dir=...)`, whereas the normal model and tokenizer loads omit `cache_dir`. The installed Hub library resolves its default cache to `HF_HOME/hub`, confirmed locally. With the shipped settings, the downloads occupy a sibling location, so an offline launch can miss prefetched weights and an online one can download a second copy of a multi-model grid. Use the library default consistently or pass the same Hub cache everywhere. [downloader](scripts/download_models.py) · [environment](scripts/env_sandbox.sh) · [model loader](src/minorsafe/registry.py)

## Dataset integrity and study design

**7. Final GPU experiments can silently use the offline corpus.** Both the runner and tomography build missing processed data with `offline=True`, including on production profiles. Autopilot subsequently skips the data phase when both Parquet files exist. In a fresh temporary directory the default offline builder returned 469 examples and 144 pairs, with zero examples from all four external sources. A later GPU run can reuse these as its final corpus. Persist and verify dataset provenance and require the production build for final runs. [runner](src/minorsafe/runner/run.py) · [tomography](src/minorsafe/methods/steering/tomography.py) · [autopilot](scripts/run_autopilot.sh)

**8. Online builds succeed after losing a required public source.** Each external loader catches download and access exceptions, logs a warning, and returns an empty list. Other sources allow the build to finish and write the normal processed filenames. The local data-phase log from 2026-11-19 23:40:29 recorded a gated XSTest failure and zero XSTest examples. This silently changes the over-refusal benchmark for downstream runs. Enforce required-source coverage and record any explicitly permitted omissions in the dataset manifest. [source loaders](src/minorsafe/data/sources.py) · [enabled sources](configs/data.yaml)

**9. Augmented prompts cross the calibration/test boundary.** The builder creates variants before splitting. The splitter hashes each variant's text independently and ignores its recorded parent. In the default offline build, 109 of 181 generated variants had a different split from their parent. **26 test variants had calibration parents**, while the project's leakage checker returned zero. A guard can train on the underlying question later counted as held out. Assign splits by canonical prompt family before augmentation and validate family overlap, including copies with item-number suffixes. [builder](src/minorsafe/data/build.py) · [splitter](src/minorsafe/data/splits.py) · [augmentation](src/minorsafe/data/obfuscation.py)

**10. BeaverTails response labels become ground truth for prompt safety.** The loader assigns the inverse of the same `is_safe` value to both `response_unsafe` and `label_unsafe`. The upstream dataset includes harmful requests paired with safe refusals marked safe. The runner discards the source answer for generation, and the resulting safe-prompt label penalizes a new appropriate refusal as over-refusal. Keep the response annotation at its original level and obtain independent prompt labels before using these rows for prompt evaluation. [loader](src/minorsafe/data/sources.py) · [success metric](src/minorsafe/eval/evaluate.py) · [upstream BeaverTails examples](https://huggingface.co/datasets/PKU-Alignment/BeaverTails)

**11. Generated obfuscations disappear from the obfuscated analysis subset.** Augmentation appends `obfuscated` after the parent's categories. Experiment selection accepts any category, but the runner persists only the first and aggregation selects rows where that single value equals `obfuscated`. Of 181 parent-linked variants in the default offline build, **zero** had that primary category, including all 62 test variants. H6 can lose its intended examples even after generating and evaluating them. Preserve all memberships and compute subset masks from them. [augmentation](src/minorsafe/data/obfuscation.py) · [row serialization](src/minorsafe/runner/run.py) · [aggregation](src/minorsafe/analysis/aggregate.py)

**12. The multiturn phase evaluates single-turn examples.** The phase dispatches the ordinary experiment runner over the dev split. Its configuration has no dialogue-specific source selection, and the production dataset builder never calls the supplied drift-dialogue constructor. All 469 examples in the validation build had one turn. The command thus completes without measuring conversational drift or per-turn early warning. Wire in the dialogue source and require turn-level observations before declaring this phase complete. [phase dispatch](scripts/run_phase.sh) · [multiturn experiment](configs/experiments/multiturn.yaml) · [dialogue builder](src/minorsafe/data/multiturn.py)

**13. Ramp-up and quantization experiments evaluate on prompts used for tuning.** Both select `dev` for measured responses. Steering setup receives the same dev pool and picks a deterministic 16-prompt subset for its parameter sweep. The evaluation sampler uses the same default seed and selection method. In the validation corpus all 16 tuning prompts appeared in the 150-example-limit evaluation. The encoder also calibrates its threshold on dev. Reserve disjoint tuning and measurement groups for the cost curves and H10. [runner](src/minorsafe/runner/run.py) · [sweep](src/minorsafe/methods/steering/sweep.py) · [quantization config](configs/experiments/quant_grid.yaml) · [ramp-up config](configs/experiments/ramp_up.yaml)

## Checkpointing and publication

**14. Incompatible experiments resume the same response shard.** The run ID hashes method, model alias, quantization, age band, parameters and label. It omits split, dataset identity, decoding settings, sample selection and evaluator configuration. Resume accepts existing example/seed keys and retains rows outside the requested set. Changing temperature, split and sample limit left all 112 main-grid IDs identical on `gpu_lab1`. An actual CPU run requested three examples, then one, and returned all three on the second run. Fingerprint resolved inputs and validate exact membership before reuse. [grid identity](src/minorsafe/runner/grid.py) · [runner](src/minorsafe/runner/run.py) · [store](src/minorsafe/runner/store.py)

**15. Resume can mark unevaluated rows completed.** After appending raw rows to a previously scored shard, pandas retains the existing `success` column and fills new entries with null. If execution stops between generation and evaluation, restart finds all response keys present and skips evaluation based on column existence. I populated that checkpoint state with the real store and resumed the runner. It finished with one null success value. Track evaluation completeness per row and require populated results before marking the shard complete. [runner, ordered evaluation](src/minorsafe/runner/run.py) · [store, append_responses](src/minorsafe/runner/store.py)

**16. Evaluation overwrites the sole generation checkpoint in place.** Generation writes a temporary Parquet file and replaces it. Both the automatic evaluation pass and the standalone eval command instead call `to_parquet` directly on the existing responses file. An interruption or disk-full error during that write can destroy the only readable copy, and resume immediately tries to read it. Use atomic replacement in both paths, or persist generation and evaluation separately. [runner](src/minorsafe/runner/run.py) · [eval command](src/minorsafe/cli.py)

**17. Analysis treats failed, unevaluated shards as measured results.** Aggregation recursively discovers response files without checking manifest status, expected row count or required evaluation fields. A temporary one-row shard with a `failed` manifest and no success measurements yielded `n_queries=1` and `success_mean=0.0`. Raw response loading for reports also ignores manifest status. Validate completeness once for all consumers and represent missing measurements explicitly. [aggregator](src/minorsafe/analysis/aggregate.py) · [analysis CLI](src/minorsafe/cli.py)

**19. Main tables and study figures mix different experiments without identifying them.** The main table and report select columns from the entire summary while omitting the experiment identity. The guard-latency plot charts every method, the recomposition plot uses every study, and the break-even plot takes the first six rows in filesystem-derived order. For example, a dev ramp-up baseline or method can appear as a main test result, and a LoRA point can appear in the encoder/decoder guard figure. Select the correct experiment and matched conditions for each deliverable and retain the cohort identifiers. [tables](src/minorsafe/analysis/tables.py) · [figures](src/minorsafe/analysis/plots.py) · [report](src/minorsafe/analysis/report.py)

## Measurement and interpretation

**20. Batch throughput is reported as individual request latency.** The generator records elapsed time for the entire synchronous call. Baseline, LoRA and steering divide it by batch size when setting each row's E2E latency, while TTFT still uses elapsed time to first token. Guards also divide batch guard and generation times. A 640 ms call returning 64 items therefore records 10 ms E2E per baseline response, even though all callers receive their results after 640 ms. This distorts latency percentiles and comparisons when batch sizes or early-block rates differ. Keep amortized resource cost and observed latency as separate metrics. [generator](src/minorsafe/generation.py) · [baseline](src/minorsafe/methods/baseline.py) · [guard](src/minorsafe/methods/guards/method.py)

**23. Guard comparisons score output decisions against input labels and omit guard work.** With the default `placement=both`, a safe prompt that produces an unsafe draft gets a high combined guard score because the output guard correctly flagged it. Aggregation compares that score only with the safe prompt label and counts a false positive. Encoder span attribution and regeneration rechecks also run extra classifier passes whose tokens never reach the token ledger. This biases both detection quality and cost in the guard comparisons. Score each placement against its own ground truth and record every moderation pass. [guard response path](src/minorsafe/methods/guards/method.py) · [encoder attribution](src/minorsafe/methods/guards/encoder_guard.py) · [detection aggregation](src/minorsafe/analysis/aggregate.py)

**24. The decoder guard reverses a valid Qwen verdict.** The calibrator tests for the substring `safe` anywhere in generated text. With the documented verdict `Safety: Controversial` and probability 0.92, its lowercased input returned **0.15** because the prefix “safety” matched. Passing the identical text without a probability returned **0.95**. The shipped GPU profiles select this model first. Parse the exact verdict field, define one controversial-content policy, and use it consistently with and without token scores. [decoder guard](src/minorsafe/methods/guards/decoder_guard.py) · [Qwen model card and output schema](https://huggingface.co/Qwen/Qwen3Guard-Gen-0.6B)

**26. Malformed judge scores can make a response pass.** The parser requires only the presence of the age field and defaults invalid or missing scores to four. The payload `{"age_appropriate":"unknown"}` returned parse success, assigned four to all four dimensions and passed the headline success rule for a lexically safe, non-refusal response. This bypasses retries. Validate the full typed rubric, retry invalid verdicts and expose unresolved cases as missing scores. [parser](src/minorsafe/eval/judge.py) · [success rule](src/minorsafe/eval/evaluate.py)

**28. Missing reference answers give prompt copies perfect reference scores.** The evaluator substitutes the user prompt when the safe reference or M0 output is missing. With prompt and prediction both “Hello there” and both references absent, the local scorer returned 1.0 for both similarity columns, SARI 100 and filter success. The GPU branch constructs the same substitute strings before BERTScore. H4 consumes the reference mean. Retain missingness, report reference coverage, and score only the rows with the required comparison text. [semantic evaluation](src/minorsafe/eval/semantic.py) · [H4](src/minorsafe/analysis/hypotheses.py)

**29. The H4 and H6 verdicts can support claims their rules never test.** An H4 fixture with zero target-word filtering for both candidates returned `SUPPORTED` when cost and similarity passed. An H6 fixture with neural recall 0.200001 versus lexicon recall 0.20 also returned `SUPPORTED`, without sample counts or a significance test. The registered claims include filtering and significantly higher recall/F1 respectively. Gate those claims on the corresponding measurements, or narrow the reported conclusions to the tested rules. [registered statements](plan.md) · [H4 and H6 implementations](src/minorsafe/analysis/hypotheses.py)

**30. Repeated prompts can turn H2 significant without adding independent examples.** H2 averages seeds but pools model/quant/example rows into one Wilcoxon test. With two prompts and positive paired differences, the actual evaluator returned `NOT_SUPPORTED` for one model. Repeating the identical observations across eight model labels changed the verdict to `SUPPORTED`. The eight runs share the same two prompts. Use matched-cell tests or a repeated-measures analysis that accounts for shared prompts and models. [H2](src/minorsafe/analysis/hypotheses.py) · [paired tests](src/minorsafe/analysis/stats.py)

**31. The H5 comparison changes the intervention and dilutes its false-positive rate.** The orthogonal arm includes a third target, `slang_toxic`, while standard StTP uses only profanity and lexical complexity. An observed difference cannot isolate orthogonalization. In addition, `slang_fpr` averages over *all* primary slang rows, including deliberately unsafe neologisms, on which `over_refusal` is always false. With one refused benign prompt and one unsafe slang prompt, the formula reports 50% despite every benign prompt being refused. Match concept sets and compute the denominator using only benign slang prompts. [standard arm](configs/methods/m3_steer_sttp.yaml) · [orthogonal arm](configs/methods/m3_steer_ortho.yaml) · [slang labels](src/minorsafe/data/neologisms.py) · [aggregation](src/minorsafe/analysis/aggregate.py)

**32. H8 can count an explicit wrong multiple-choice answer as correct.** The MMLU parser returned A for “A brief explanation follows. The answer is C.” because its first alternative permits any initial article A. The scorer also awards credit if the gold choice text occurs anywhere in the explanation, even when a different letter was selected. On the lab profile only 25 MMLU items per arm feed the accuracy delta, so one error moves it by four percentage points. Parse the final explicit choice, reject ambiguous output and remove incidental substring credit. [capability scoring](src/minorsafe/eval/capability.py) · [lab profile](configs/hardware/gpu_lab1.yaml)

## Additional execution and measurement failures

**33. The supplied Docker image fails its own benchmark preflight.** The Dockerfile copies neither Git metadata nor `.gitignore`. In that layout, `check_credential_safety` requires a literal ignore entry even when there is no credential file. Running the check against a directory with those same three files absent returned an error. Preflight promotes it to a hard failure, blocking the phase script in the image. Make the check aware of installed/container layouts or include the required ignore policy in the image. [Dockerfile](Dockerfile) · [preflight](src/minorsafe/hardware.py) · [phase wrapper](scripts/run_phase.sh)

**35. The 24 GB profile ignores its large-model QLoRA requirement.** Grid expansion for the real main experiment on `gpu_24gb` produced four large LoRA arms, all BF16. The profile sets `lora_large_mode: qlora`, but the only Python reference to that field is its schema declaration. The trainer enables k-bit preparation only for a quantized run. This changes the advertised intervention and memory requirements on the hardware it was designed to fit. Resolve the effective precision during grid expansion and persist the resulting treatment. [24 GB profile](configs/hardware/gpu_24gb.yaml) · [grid](src/minorsafe/runner/grid.py) · [trainer](src/minorsafe/methods/lora/train.py)

**38. H7 accepts in-sample tomography as held-out separability.** When a concept has calibration pairs but no evaluation pairs, tomography records `insample_fallback` and calculates AUROC on the pairs used to derive the axis. The H7 consumer averages the numeric AUROCs without inspecting the saved evaluation modes. Such a concept therefore influences the size comparison as if it had independent observations. Require held-out measurements for H7 and propagate missing coverage to the verdict. [tomography](src/minorsafe/methods/steering/tomography.py) · [AUROC calculation](src/minorsafe/methods/steering/extract.py) · [H7](src/minorsafe/analysis/hypotheses.py)
